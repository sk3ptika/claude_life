# Weekly Review — vollständige Checkliste

Dauer: 30-45 Minuten. Fester Wochentermin. Ohne festen Termin verfällt das System innerhalb von drei Wochen.

## 1. Sammeln (5 min)

- [ ] `00_Inbox/` öffnen, jedes Item nach der Zuordnungs-Entscheidung aus SKILL.md verarbeiten
- [ ] Lose Notizen aus Kopf, Handy, Zettel nachtragen
- [ ] Downloads-Ordner und Kamera-Karte kurz prüfen: liegt dort etwas, das ins System gehört?

Zielzustand: `00_Inbox/` ist leer. Nicht "fast leer".

## 2. Projekte prüfen (15 min)

Für jedes Projekt in `01_Projekte/`:

- [ ] Ist das Ergebnis noch dasselbe wie bei Anlage?
- [ ] Gibt es einen nächsten Schritt, der in einem Zug erledigt werden kann?
- [ ] Hat dieser Schritt einen Termin?
- [ ] Gab es diese Woche Fortschritt? Wenn nein: seit wann nicht?

Regel: Kein Fortschritt in zwei aufeinanderfolgenden Reviews → Projekt wird explizit entschieden. Drei Optionen, eine muss gewählt werden:

- **Neu schneiden** — Projekt ist zu groß, kleineres Teilergebnis definieren
- **Pausieren** — nach `03_Ressourcen/irgendwann.md` verschieben, Ordner ins Archiv
- **Streichen** — Ordner ins Archiv, Begründung in `_projekt.md`

"Weiterlaufen lassen" ist keine Option.

## 3. Bereiche prüfen (10 min)

Für jeden Bereich in `02_Bereiche/`:

- [ ] Welchen Standard habe ich hier definiert?
- [ ] Wird er aktuell gehalten?
- [ ] Wenn nein: entsteht daraus ein Projekt, oder senke ich den Standard bewusst?

Typische private Bereiche: Finanzen, Gesundheit, Wohnung, Familie/Freunde, Beruf, Warhammer, Fotografie, Technik.

## 4. Vorausschauen (10 min)

- [ ] Kalender der kommenden zwei Wochen durchgehen: entsteht daraus Vorbereitung?
- [ ] Maximal 3 Projekte für die kommende Woche als aktiv markieren
- [ ] Für jedes aktive Projekt: konkreter nächster Schritt mit Tag

Mehr als 3 aktive Projekte im Privatleben führen erfahrungsgemäß zu null abgeschlossenen Projekten.

## 5. Protokoll

Datei `_system/reviews/YYYY-Www.md` anlegen mit:

- Inbox-Stand vorher/nachher
- Projekte: abgeschlossen / neu / gestrichen / pausiert
- Bereiche mit Handlungsbedarf
- Die 3 aktiven Projekte der kommenden Woche
- Eine Beobachtung: was hat diese Woche das System gestört?

Die letzte Zeile ist die wichtigste. Nach vier Reviews Muster aus diesen Beobachtungen ableiten.

## Monatlich zusätzlich

- [ ] `04_Archiv/` des laufenden Jahres sichten: stimmt die Ablage?
- [ ] `03_Ressourcen/irgendwann.md` durchgehen: was wird jetzt ein Projekt, was wird gestrichen?
- [ ] Backup prüfen (Google Drive allein ist kein Backup — siehe `konventionen.md`)

## Quartalsweise zusätzlich

- [ ] Bereichsliste prüfen: fehlt ein Bereich, ist einer überflüssig?
- [ ] Jahresziele gegen tatsächliche Projekte halten. Abweichung benennen, nicht wegdiskutieren.
